## Integration classification

Keep metadata catalog (work/edition identity), content source (chapter/pages), list import (wanted works), release indexer (release search), download client (job lifecycle), tracker (per-user progress/status), external reader (library/progress API) and notifications as separate contracts. The [integration inventory](INTEGRATION-INVENTORY.csv) records 25 groups; it is not a claim every individual provider works or is approved. I = path-only lead; C/L = selected declaration/logic. Registry entries establish registration, not service availability, rights or feature completeness.

Notable distinctions:
- Mangarr: twelve direct-source registrations including metadata-only sources, plus Nyaa and configured Torznab. Do not count all twelve as download providers.
- Maki: interchangeable Prowlarr/Jackett and three torrent clients; local MangaBaka data; a generic tracker service and five tracker class paths. Verify actual registrations and per-provider implementation.
- Uchiyomi: four named tracker types; source capability surface includes pagination/creator search, language and shared rate group. Respect rate limits and deny access when refused.
- Manga-arr: list import dispatcher includes AniList user/top/popular, MAL user and custom RSS. Release RSS is a different operation; exact acquisition authority still required.
- Kavita: paid Kavita+ external metadata/scrobbling service distinct from free local reader; do not depend on premium entitlement without owner approval.
- Suwayomi: seven registered tracker services in pinned source.
- Mihon: twelve registered tracker services, including three self-hosted connectors. Comick is an additional observed branch registration, not verified as available in latest published release.

## Proposed unified contracts and safety requirements

| Contract | Minimum independent capabilities | Acceptance conditions |
|---|---|---|
| Metadata | Search, detail, aliases, cross-IDs, field provenance, optional related/group/volume/release evidence | Exact known ID or reviewed match; multiple qualifying identities or conflicting IDs stop auto-link; preserve user locks |
| Content source | Search/pagination/creator optional, series detail, chapter list, authorized page retrieval, capability and language | Respect entitlement; shared provider rate groups, no unsupported controls, typed missing/refused/unavailable; no access-control bypass |
| List import | Source/account/list/status, schedule, preview, exclusion, dedup, unmatched retry | Does not download without approved acquisition policy; complete vs truncated/failure distinguished; no automatic deletion when absent |
| Indexer | Protocol, endpoint, secret, selected indexers/categories, search and capability test, rate-limit state | Secrets bound to origin, bounded parser, persisted retry deadlines, partial outage distinguished from empty |
| Download client | Auth test, exact add/status/remove/cancel, path map, category/label, protocol/client/job IDs, explicit data-delete flag, seeding policy | No job adoption/removal solely from matching title or label; acquisition authority required; never delete data by default; protect hardlinks |
| Tracker | Per-user authentication, search/bind, read/write progress, status, score, dates/privacy as supported, retry/reconnect | Separate consent for reading/rating/backfill, no unsupported field writes, private entries fail closed, no duplicate outbox events |
| External reader | Scoped account, file/edition identity, access, progress/notifications | Single authority, no sync echo, explicit conflict policy, no unauthorized cross-user access |

Rate limit policy: preserve provider-requested minimum delay even where an upstream caps retry headers; defer rather than bypass or shift traffic to avoid controls. Token failure policy: distinguish auth rejected/expired/unreadable from network/server failure. Don't log credentials, callback tokens, API keys or private reading activity. Scope all user data and verify redirects before credential forwarding.
