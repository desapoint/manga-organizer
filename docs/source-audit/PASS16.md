## Proposed capability and status boundaries

| Adapter | Submission | Observation | Central library admission |
|---|---|---|---|
| qBittorrent | Selected client submission and scoped hash evidence | Category/status; distinguish moving/checking from verified stable bytes | Verify stable archive, coverage, object identity, root and receipt |
| SABnzbd | Pass 13 addurl and exact nzo_id | Pass 14 history/queue, bounded response and absence risks | Client-owned completed path, guarded mapping and verified import |
| NZBGet | Pass 13 append returns ID | Completion/import not established; Pass 16 client-type inference lacks NZBGet | Capability remains incomplete; do not announce full support |
| Suwayomi/Mihon | Pass 10 engine queue/worker evidence | Engine state and worker success advisory, requester/engine-scoped identity | Separate verified import from engine terminal state |
| Direct/archive | UC route enqueuer and visibility; earlier KR/MK providers | Bounded rate/retry, pause and stop; verify individual actual consumers | Same content/edition and no-clobber receipt checks |
| Kobo | Reader/device sync, not an acquisition client | Scoped change cursor and preferences | Never treat entitlement or read status as physical acquisition authority |

Proposed durable handoff: request -> validated intent -> submitting -> acknowledged OR uncertain -> reconcile exact owner snapshot -> transfer -> artifact stable -> verifying -> duplicate review -> import journal -> durable imported receipt. Transport timeout, empty history window, disabled client, stopped worker and missing engine event are distinct states. Do not retry an ambiguous mutation simply because an in-memory claim was released; persist before side effects and query with appropriate client identifiers. Separate client health from business acceptance and result certainty. Use the Pass 9/10/15 safety contracts; no automatic physical deletion. User-level visibility and requester rights must be applied before exposing identifiers and after permissions change.

Settings must show requested, validated, persisted and effective state; configuration changes need a revision, scoped credential origin, consumer acknowledgement and error feedback. UI placeholders are not defaults or validation. Selected KR/MK UI fields, MH Wi-Fi worker and KV sync-limit consumers add evidence, not a complete per-key registry. User-specific reader integrations do not confer management rights.

## Additional qualification

- **P16-01:** Client progress 100%, payload moving/checking or incomplete — No verified import before stable readable artifact, expected coverage and strong digest.
- **P16-02:** Remote add accepted but reply lost, 403, timeout or restart — Durable uncertain submission before network effect; query exact client before retry; no duplicate or silent success.
- **P16-03:** Changed remote path, ambiguous prefix, root replacement or shared seeding file — Component-aware mapping, exact owner, root epoch and no destructive client action; preserve seed.
- **P16-04:** Same download ID on two servers, rotating release URL, NULL owner — Independent exact instance/protocol/ID keys; legacy ambiguity blocked; scoped GUID and receipt.
- **P16-05:** NZBGet append returns ID but completion source unavailable, incomplete history or non-200 — Capability advertised per lifecycle stage; absence is unknown; no cleanup or imported state.
- **P16-06:** Worker dies, cooldown survives restart, queue remains inactive or cancellation races claim — Fenced durable ownership, bounded backoff, reconcile state before resubmit; no terminal status from silence.
- **P16-07:** Hidden series, unauthorized requester, pause or stop during archive download — Reject without disclosing title; preserve other requesters and existing artifacts.
- **P16-08:** Settings edit during active job, invalid/masked credentials, changed origin — Validate and persist revision; apply effective settings explicitly, reauthorize side effects, surface failure.
- **P16-09:** Empty engine queue, stopped worker, completed event without verified file — No imported status; reconcile engine snapshot, verify artifact and durable central import receipt.
- **P16-10:** Kobo paginated changes, retry/revocation, restricted library or age — User-scoped cursor and access check on every delivery/mutation; no cross-user disclosure or physical file deletion.
