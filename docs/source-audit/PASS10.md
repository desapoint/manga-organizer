## Major design consequences

1. Isolate extension execution in separately versioned Suwayomi runtime. Support legacy APK and JAR where the qualified runtime supports them, not direct Android execution on Windows. Treat code as untrusted; require origin, artifact identity, compatibility and consent; do not equate package name or newer version with same signer.
2. A shared engine queue and per-user download requests are distinct. Central queue has durable job and requester records, adapter idempotency keys and engine-instance-specific chapter identifiers. Cancel one requester without removing another's work; global start/stop/clear are privileged. Never implicitly enable physical delete-on-read.
3. Subscribe for updates, recover through authoritative snapshots after disconnect/restart. Engine completion, filename, count and downloaded flags do not prove integrity. Stage outside managed library, inspect archive/path/size/order/coverage/hash and publish via Pass 9 contract. A successful handoff is recorded independently; do not remove engine copy until verified and explicitly authorized.
4. Mihon backup stores are migration data, not trusted executable configuration; preview, validate, redact sensitive metadata and avoid automatic extension install. Checked-in client schema is concrete comparison evidence, not a live schema of the pinned server. Client snapshot selected field comparison does not establish nullability, permissions or full compatibility.
5. No automatic permanent deletion; distinguish source-specific request, engine completion, verified import, and per-user progress.
