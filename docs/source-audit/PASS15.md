## Required outcomes: proposed safety contract

Separate read-only inventory, candidate comparison, reviewed plan, execution authorization, operation-owned staging, verified publication, reference commit and reviewed quarantine. Do not substitute a rebuilt plan for the user's reviewed version. Bind plan revision to actor, root/storage identity, expected files and strong digests, coverage, current references, relevant configuration and expiration. Check authorization at execution and recovery, not merely preview. Keep physical object identity separate from content identity and bibliographic match; only verified exact duplicates may be considered for reclaim, never estimate reclaimable bytes from aliases alone.

Physical operations and catalog state are not one atomic transaction. A journal must record ownership/intent before side effects, verify no-clobber publication, record durable receipt, commit references and explicitly acknowledge cleanup. Preserve original/unique content; copy-on-write for shared hardlinks. A failed or interrupted operation must expose unresolved state. Recovery does not confer new destructive authority. Require explicit reviewed quarantine, not permanent deletion by default. Progress and tracker changes cannot authorize deletion.

Extension permission boundaries: upstream SW tests explicitly intend plain update without install/uninstall rights; this resolves the earlier question of intended behavior in selected source, not actual security verification. Propose separate central permission for package updates, provenance changes, external installation, global queue and file deletion; engine credentials isolated and least privilege. Signature metadata is not verification. Do not treat successful mutation response for nonexistent package as installation proof.

## Qualification gates

- **P15-01:** Reviewed plan expires or configuration/chapter set changes. Acceptance: Reject stale request, show difference; never silently substitute current plan.
- **P15-02:** Crash/DB failure between physical action and reference commit. Acceptance: Durable journal, retain original where possible, verify receipts on restart and block ambiguous operation.
- **P15-03:** Case-only rename, shared volume, occupied destination. Acceptance: Preserve all chapter mappings; no-clobber on qualified filesystem; original and destination unaffected on refusal.
- **P15-04:** Candidate survivor missing, ambiguous, misparsed or different coverage. Acceptance: Keep files and references; no duplicate resolution based on names alone.
- **P15-05:** File changes, hardlink alias or root alias after preview. Acceptance: Revalidate digest, object identity, root epoch and reference graph; refuse unsafe retirement.
- **P15-06:** Unauthorized actor or stale bulk item; one item fails. Acceptance: No unauthorized effects; return durable per-item outcome, no false batch success.
- **P15-07:** Multi-root move with occupied secondary root or concurrent read/write. Acceptance: Fence operations, preserve privacy, IDs, progress and sidecars; recover all roots.
- **P15-08:** Metadata enrichment of hardlinked archive, concurrent source replacement. Acceptance: Copy-on-write, source bytes unchanged, stage independently verified; no mutation of seeding file.
- **P15-09:** No-replace unsupported or crash after publication. Acceptance: Qualified primitive only; keep both names if uncertain, reconcile receipt without blind retries or overwrites.
- **P15-10:** Slow active write passes scan cap or root disappears. Acceptance: Treat readiness as unknown; read-only scan findings cannot authorize deletion.
- **P15-11:** No permission, install-only, uninstall-only, update-only, external install. Acceptance: Enforce explicit central role; denied requests produce no external action; verify package trust.
- **P15-12:** Changed signer/store, same package version, unsigned JAR/APK. Acceptance: Quarantine before loading; require verified provenance and admin approval; reject unsupported signer.
- **P15-13:** Pending-delete drain, unavailable source, failed delete or restart. Acceptance: Retain durable intent until verified; cache reflects actual files; no automatic physical deletion.
