## Cross-repository implications

- A missing key, explicit empty value, inherited setting, invalid value, unavailable config store and disabled operation are different states. KR ignores unknown keys in set_many, MK deletes whitespace values at storage layer, KK has permissive language fallbacks, UC archive read failure falls back to unpaused/default rate, SW per-key updater may catch failures. Do not blindly inherit these semantics.
- Persist config revision and report effective value, scope, origin, bounds, restart/reconfigure requirements and last apply error. Validate the complete candidate before writing; reconfigure consumers with an explicit outcome. No guarantee that persisting a key applies it to runtime.
- Treat restrictive rules as gates, not scores: language/edition mismatch, permissions, source disable, protected roots, licensing and content verification cannot be overridden by a higher quality score. Unknown data must remain unknown.
- Scope global server config, deployment locks, library overrides, series overrides, acquisition profiles and user/device reading preferences separately. No universal precedence chosen for settings that do not share scope.
- Root routing preview must match runtime and use only allowed, available roots. No silent destructive relocation on policy edits. Separate source concurrency, page concurrency, quotas and rate limits, respect refusal and terms.
- Preserve individual metadata field rules and provenance; distinguish external paid service entitlement from local independent functionality. Secrets are write-only, destination-bound and redacted. Progress never implicitly authorizes file deletion.
