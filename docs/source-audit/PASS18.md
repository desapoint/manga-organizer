## Packaging and runtime

Windows: Maki installer explicitly rejects appdata overlap, drive roots and unrelated occupied directories, runs with lowest privilege and delegates setup to Velopack. These are source-level defenses, not qualification against junctions or uninstall behavior. Uchiyomi desktop restore refuses server-format config archive; do not advertise interchangeability. Central Windows standalone must run without Docker, keep data outside install path, support graceful shutdown and qualified signed updates; remote mode must not accidentally launch a second authority.

Unraid/Docker: KR optional IDs leave default root if unset, MK maps IDs with gosu, UC supports root drop and external DB/embedded PG, KK image declares nonroot, KV PUID/PGID code commented. Do not normalize these differences into a false common contract. Proposed explicit numeric runtime user, writable local config preflight, no automatic library chown, no blanket root privileges, mount identity/fencing and separate liveness/readiness. UC refuses PG major mismatch and supervises embedded PG on private socket; external DB needs separate qualification.

## Backup and restore contract

| Reference | Observed boundary | Required central improvement |
|---|---|---|
| MK | DB/WAL/SHM moved, migration check and exception rollback, config copied afterward | Durable restore transaction and coherent config/DB/key revision; retain versioned rollback copies |
| UC | Safety copy, stop BFF, restore DB then config; restart even on partial config failure | Maintenance fence until verified restore; explicit rollback/forward recovery |
| KK | SQLite online backup, offline restore with key validation and prior DB/key | Enforced offline writer/checkpoint precondition; preserve WAL consistency and crash journal |
| KV | Serialized VACUUM INTO, WAL mode restored, staged asset/config zip | Consistency manifest, missing asset diagnostics, protected secrets/logs and verified archive publication |
| MH | Batch fallback to per-manga restore and error recording | Preview, per-entry results, transaction trace and explicit category/identity mapping |
| SW | Mutex-protected HOCON direct write then in-memory update | Atomic staged settings write and durable effective revision; verify actual settings updater caller |

Proposed backup set: database/schema version, configuration revision, operation receipts and queues, provenance/edition/progress data, secrets under separate protected policy, asset manifest with missing/excluded entries, and root mappings (not the library bytes unless separately selected). Do not silently restore revoked tokens, untrusted extension stores/signers, old credentials or active destructive intent. Quiesce writers or use verified snapshot contract, validate in isolation, stage all files, commit durable phase and acknowledge only after successful health/ACL/mount checks. Restore remains fenced from automatic downloads and filesystem mutation until verification; use explicit rollback or forward recovery. No archive or media deletion by default. Proposed controls, not implemented behavior.
