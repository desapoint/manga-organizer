## Important differences

- KR and KK are automation-oriented references; reader behavior not established by these schema/authorization inspections. KR's chapter path and number uniqueness are insufficient for multiple releases/editions and user reading anchors.
- MK distinguishes acquired page count/quality from post-conversion view. UC supports presentation-only split/join/crop and timestamp-based resume. Use original page identity and separate transformation maps.
- UC's current progress logic treats resume, completion, private and incognito differently: latest event controls page, completion normally sticks, explicit silent marks override completion, incognito keeps resume but skips activity/tracker. This is a reference, not a fully verified conflict algorithm. Late explicit marks/completion and privacy transitions need more tests.
- KV supports distinct book scroll/Kobo span, image page bookmarks and text annotations. MH bookmark flag is chapter-level; do not conflate these. KV bulk read operations update total reads; proposed organizer should distinguish actual reading sessions.
- SW pinned branch separates chapter and manga user state and patches per-user progress with page clamping and KOReader sync. Release parity unresolved, see pass 4.
- MK legacy user migration backfills user 1; MH migration 19 rebuilds tables and views. Do not adopt arbitrary owner backfill or untested destructive downgrade.
- Private data includes progress, cache, covers, screenshots and export; restricting only library listings is insufficient.
