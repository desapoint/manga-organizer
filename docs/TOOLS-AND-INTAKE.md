# Tools, intake and library navigation

This is the owner-confirmed workflow for the Tools and Import follow-up. Reuse the existing scan, series, duplicate and file-operation services. [Implementation backlog](EXPANDED-BACKLOG.md)

## Navigation and ownership

| Surface | Primary job |
| --- | --- |
| Library | Browse the published scan inventory, covers, linked metadata, chapters and volumes. Keep reader links where there is a supported local release, as well as metadata editing and reading-status shortcuts. Show eligibility on the server before pagination and counts. |
| Import | Discover and scan intake folders, then review associations, metadata, artwork and destination. Start on **All scanned files**. **Needs attention** focuses on unresolved intake issues. |
| Tools | Provide a dedicated desktop and mobile destination for Duplicates, Versions and alternatives, Associations, Organize and Maintenance. Each module has its own scoped index and filters. Link into the relevant module from Library or Import when useful. Reuse one implementation for each action and its authorization. |

Use the existing workspace navigation and focus conventions. Deep links retain module, root, series and active filters. The inspector stays stable while the pointer highlights a candidate or chapter. Use the current selection and table components so keyboard and mobile workflows remain available.

## Association and metadata queue

Give each Tools module a focused work queue with issue filters, visible reasons and the next action on the row. Keep the queue position after a save and surface the next unresolved row. Use a compact comparison for routine decisions and open the detailed inspector when more evidence is needed.

The Associations and Metadata queue prepares AniList candidates using the indexed series name and known alternative titles. Show the local name, proposed result, cover when available, matching title evidence and direct AniList link. A clear candidate gets an inline **Confirm match** action. Show competing results for ambiguous names, and keep manual search and manually entered metadata available on every unresolved row. Saving a match uses the existing server metadata persistence and is explicit. Suggestions and provider failures never change a series association by themselves.

On successful scan publication, enqueue one initial lookup for each newly discovered, unresolved series. Compare the new published series against the previous inventory and retain an attempted-lookup record so repeat scans, worker restarts and reappearing known series do not look new. Reuse saved results across requests for the same normalized title. Imports use the same bounded queue. Failed, interrupted and unavailable scans do not enqueue suggestions.

Series already in the inventory when this feature is installed can be selected through **Rescan this page**. The background lookup uses the series name and compares AniList titles and aliases for exact normalized matches. Several plausible results are available in **Review matches**, and every unresolved row supports manual assignment.

A single bounded worker drains the queue independently of scanning, saves ranked suggestions locally and backs off using provider rate-limit responses. Paginate the local queue before displaying suggestions. Opening, refreshing and paging through the module only reads saved data. **Rescan this page** adds only the visible series to the lookup queue, and coalesces requests for work already queued. Keep prior suggestions usable during refresh, and report queued, no-match and retry states. Manual search still requests candidates for the series the user selected. Revalidate the current series before applying confirmation so an older queue row cannot overwrite a more recent assignment.

Rescanning a page prioritizes its visible series ahead of the ordinary scan backlog. Manual search and metadata requests take priority over queued requests that have yet to start. A running provider request finishes under the same queue entry, and all provider requests share AniList pacing and cooldown. Confirming a cached suggestion is a local write that can run during scan discovery, hashing and artwork extraction. Scan publication briefly takes a catalog write lock. A scan that first obtains a content identity for an existing path-only group can queue the group's first lookup.

Use **File associations** within the same module to find indexed files without a confirmed series. Confirm the current suggestion when metadata is already saved, or search the local metadata catalog to choose another series. Import’s flat file view exposes the same correction action. Organize also exposes it for already confirmed files. Preview the chosen series and the affected indexed locations. Applying the correction links the exact content identity across all locations. File bytes, per-file reading progress, and release tags are preserved. Review chapter coverage separately when correcting the series. A fresh scan applies the saved association after a manual rename or move.

Import starts with a full-width scanned inventory and shows cached AniList proposals on collapsed series rows. Open intake details with the series info icon or by selecting a filename. Enlarge the local cover, inspect an AniList match and its external listing, search manually, or confirm a proposal from the row. The close-match filter shows unresolved series with one exact normalized AniList title or alias. Filename preparation separates recognizable convention and creator prefixes and release notes from candidate doujin titles. Keep franchise annotations as filename evidence. Preserve ambiguous mixed-language title text for review. Expanded groups expose **Edit metadata**, which opens the manual form immediately. Fill missing fields or replace the draft using a linked or suggested AniList listing, then review and save. AniList search remains available on the collapsed row. A search result can be reviewed in the editor before saving. Use **Split from this series** to review an outlying file separately. Splitting preserves the path and file bytes and survives scans of the same indexed location and content. A confirmed association shared by byte-identical copies is corrected using the shared association action in Tools. Release-language and edition tags still require manual assignment. Future work can suggest those tags before confirmation.

The scanner recognizes compact convention labels such as `(COMITIA101)`, `(CR31)` and `(SC2018 Summer)`, self-published releases with a `(Doujinshi)` prefix, and numbered release labels such as `01. [Creator]`. Filename details retain release notes, alternate titles and ranges. The Import list and **Find on AniList** use the detected title, and the background lookup uses the same title preparation. Original filenames and folder paths are available through the file, folder and series details. A folder scan can regroup affected unresolved files and queue new proposals. **Rescan this page** can refresh an existing proposal before scanning the folder. Saved metadata and associations follow the content identity.

The AniList preview separates the synopsis, publication details, tags and actions. Consecutive line breaks collapse to a single paragraph break. Spoiler tags keep their size and position as filled placeholders after the regular tags. Use the eye button beside **Tags** to reveal or hide their names.

Import uses equal-width title and AniList columns on wide screens, with fixed locations for confirmation, search and details. Covers use a 2:3 portrait frame. AniList matches with artwork supply both row covers, and the title column uses local artwork when the match has no cover. On narrow screens those columns stack. A match being saved disables its row and dialog actions. Task feedback appears in toasts so that confirmation and failure messages keep the inventory in place.

Confirming a match or saving metadata from an Import review associates the verified files represented by that review. The server checks that each reviewed location still holds the same content in the same group. Scan publication retains the series link and continues to group incoming files normally. Newly indexed files, including new locations with identical bytes, need their own confirmation. A verified move can carry the original file's review to its new location.

In an expanded Import series, use the header checkbox to select all eligible files under the current intake filter, including files on other pages. When a series spans several parent folders, the folder checkboxes select files from one folder at a time. The round row controls select individual files. A horizontal line in the header or folder checkbox indicates a partial selection. Checking or clearing a release keeps the file row and its columns in place. Applying bulk tags clears the selection. Opening or canceling the preview preserves it. Each file has its own release tag action at the end of the row. File details link to the Duplicates tool when identical bytes are indexed in multiple locations.

The metadata editor shows the current AniList link or proposed match and what saving will do. Selecting a suggestion stages the link. Removing a match stages a local-only save and keeps the editable fields and tags. For an already linked series, the change applies to the shared series record and retains its files and reading history.

When confirming manual metadata or editing a series, enter regular tags and spoiler tags one per line. Saved tag edits are kept through AniList refreshes, and **Use AniList tags** restores the linked listing’s tags. Regular tags appear in the Library tag picker and work in dynamic collections. Spoiler tags stay behind the reveal control and out of tag suggestions.

Each confirmed series owns one metadata record. Files reference it by internal series ID, and an optional unique AniList ID resolves to that same record. **Choose existing series** and confirming a previously linked AniList listing both reuse the stored record and its metadata. The upgrade consolidates existing AniList duplicates and keeps their file associations, chapter progress and verified edition coverage. When older records disagree, the upgrade keeps the metadata from the series shown as primary in the Library. Use **Replace from AniList** in the editor to intentionally refresh the shared details.

Use the pencil action on a Library chapter or volume to save its title and summary, including entries without a local file. These details belong to the series and its chapter or volume number. Archive coverage is edited separately using **Assign volume or chapters** in the Files tab.

Under **Edit metadata → Series cover**, choose a scanned archive or folder cover, use the linked AniList artwork, or upload a JPEG, PNG or WebP image up to 8 MiB. A chosen local image is saved in the catalog as a WebP cover. The preference survives scans, file moves and artwork-cache clears, and **Use automatic cover** restores the scanner’s selection. With an AniList link, the preference applies to that AniList entry across the catalog.

## Duplicate and version workbench

- **Duplicates** lists candidate groups by series across authorized libraries. Filters apply before pagination and counts. Include library, match class, review status, and file scope. Show exact copies and aliases separately. Attach affected files and the reason each candidate was detected. Preserve navigation back to the series summary and its filters.
- Tools opens a series workbench with **File duplicates** and **Series overlaps**. File duplicates can be scoped to the selected file and its candidates. Matching-span pairs default to the compact comparison. Compare archive format, image-page counts, ComicInfo, covers, path, accessible page samples and available release attributes. Same-number volumes with unresolved chapter labels can be compared here and show uncertainty. The fast flow keeps the retained file and chosen action visible and still uses the existing guarded preview and confirmation.
- **Series overlaps** opens the full chapter coverage map for the entire series, including partially overlapping volumes and collections. Use the current volume colors, tile-local chapter stripes, chapter inspector, and clickable and hover highlights. Keep the whole-file coverage and loss preview available before removal. [Duplicate evidence and safety](DUPLICATE-AND-TRASH.md)
- **Folder comparison** lets you inspect two locations for the same indexed series. It shows exact bytes, overlapping chapter coverage, and files with no verified counterpart. Pick a folder to keep or keep both. A review can remove only verified exact copies from the other location by moving them to recoverable quarantine within their original, scanned, managed library. Verify the retained file again before parking the source, including when the retained file is in a separate configured library. Different releases and files without a verified counterpart stay in place.
- **Series review decisions** records Keep files, Defer, or Reopen for one finding type in the selected series. The Duplicate queue defaults to **Needs review** and can also show kept, deferred, or all findings. Exact-byte findings have their own decision. A change to the indexed candidate set, availability, or relevant coverage and release evidence returns the finding to the review queue while keeping the previous decision in history. Review decisions update queue state. Reviewed storage actions continue through their own previews.
- **Versions and alternatives** shows only series with multiple releases for the same resolved content span or a reviewable candidate span, including same-number volumes that require verification. Exact byte copies alone belong in Duplicates. Filter versions by language, color, censorship, edition, group and review status. Enable the same release editor for selected candidates and for single or bulk files in Associations or Import even when there is no duplicate. Persist language, censored/uncensored/mixed/unknown, black-and-white/full-color/partial/unknown and other supported fields as independent release facts. Retain evidence and explicit owner overrides. Future acquisition can read the saved fields to request multiple languages or versions under the separately approved acquisition policy. [Release attributes](RELEASE-IDENTITY.md#release-attributes-and-evidence)
  - Bulk tag correction is scoped to selected files on one page. Preview each path and its current value for the chosen field. Apply that field to all selected releases in one transaction, preserving other fields. Exact-byte locations share a tag record. If a file moves or a tag changes during review, reopen the preview before applying the batch.

Versions groups distinct byte identities by indexed chapter span and shows same-numbered volumes with incomplete coverage as review candidates. The file editor is shared by Versions, duplicate comparison, Import and Organize. It records explicit owner tags on the content identity and detects stale file identities or tag revisions at save time. Exact-copy findings retain their existing evidence and workflow.

## Intake issues and destination

The scanner still owns discovered file rows and content identity. Library reads the last published scan state. A failed or unavailable scan preserves its previous inventory. Import exposes unresolved files even when they are filtered out of Library. Surface nonexclusive issue fields for missing or unconfirmed association, no linked series, missing required metadata and missing cover art. Issue filter selections and counts use the same server query. For a dual-purpose root, use one inventory entry and present the view states separately.

Library shows scanned files even in dual-purpose folders only after a series is confirmed and it has either AniList-linked or owner-entered metadata. A missing cover is an Import attention issue and the item can still appear in Library. Track ComicInfo and file or folder artwork as evidence. A future automatic metadata agent can fill evidence through the same path after its own approval and tests. Use the same confirmed series and metadata check before publishing an intake transfer. Manual metadata is a full route when AniList has no suitable match.

Numbered filenames with a shared creator and title can form one suggested series when two or more distinct chapter numbers are present. An alternate creator name in parentheses can match the same creator shown on its own. Publisher and resolution suffixes are retained as filename evidence.

In Import’s series list, use **Select series to group** to choose two or more entries. Enter a shared title or include a single saved series as the destination. Review the group as intake, confirm it with manual metadata, or explicitly link it to AniList. This action preserves media paths and file identities. Correct conflicting saved associations in Tools before grouping those files.

The Library groups files that were explicitly linked to the same AniList ID within the selected library folder. The series page includes the files, chapters, volumes and reading history from those confirmed groups. Existing links can still open the grouped page. Import keeps local groups available for correcting an association. Library folder selection continues to limit the visible inventory.

Library counts, series details and release pickers use the same per-file admission rule. A new file that matches the name of an existing series appears under **Unconfirmed association**. Confirm it from Import or Tools → Organize to apply the saved association to that indexed content. **No series suggestion** isolates files without a candidate title. **Missing metadata** and **Missing cover** may overlap either association state. Updating series details from Library saves the metadata for the confirmed series. Import and Organize provide the assignment actions for newly scanned files.

Persist one **Target library** root ID per Import folder. Every eligible item in that folder uses the same target, including mixed-series batches. Show the mapped root and planned relative paths before transfer. Missing, removed or unavailable targets leave the files in intake and identify the configuration issue. A dual-purpose folder mapped to itself needs no cross-root move. The first slice uses reviewed transfers with the current no-clobber previews, permissions, revalidation and recovery journal. Automatic movement remains a later qualified path under the prior intake policy. Defer rules that choose targets by language, version, series or other filters. [Current intake and batch flow](FILE-ORGANIZATION.md#import-intake-and-association)

Set the source folder’s target in **Library settings**. Use **Transfer to library** for one confirmed file or **Review intake transfer** for a batch. Both show the saved target and editable relative paths. Available managed access and current file association are checked during preview and again before applying. The file operation history keeps the original recovery route even if the saved intake target changes later. Ordinary organization within an intake folder remains available through its managed move controls.

A dated series uses the `Title (Year)` folder and a file name such as `Title Vol.3 Ch.24.cbz`, `Title Ch.10.5.cbz`, or `Title Vol.3.cbz` for a whole volume. Preserve the existing extension and keep both files by default with the existing variant suffix allocator. A confirmed series plus a known chapter or volume is enough for a reviewed transfer. Enter a volume without chapters to save a whole-volume assignment to the content identity. The volume remains readable and can be transferred before chapter mapping is available. Missing artwork and untagged language or edition stay available for review in Tools. Volume-to-chapter discovery from providers and automatic release attribute suggestions remain follow-ups. [Naming behavior reference](https://github.com/OrbitMPGH/Maki/blob/0de45e926f368e23ace4dba04e2211d1de83aadb/src/Maki.Core/Naming/NamingDefaults.cs)

## Volume navigation

**View files** opens Files with the selected volume applied by the server before counts and paging. The filter matches volume hints, linked chapter coverage and verified edition membership. A clear action returns to all series files. **Read volume** opens the reader when the catalog has a supported volume archive in an available root, including archives with unresolved chapter assignments. The reader resumes each archive at its saved page. Verified chapter offsets belong to the separate reader mapping work.

The chapter list shows verified chapter labels and expected whole-number chapters up to the known release total. It distinguishes missing local files from readable releases and saves read status for either. An aggregate total leaves volume assignment and special chapter labels unverified. A confirmed finished AniList series with one chapter supplies Chapter 1 for an otherwise unnumbered associated file. **Read volume** opens the most recently read release, or the first indexed path when there is no reading history. **Choose release** remains available for alternate copies. **Link chapters** edits a volume's chapter list even when no local file has been assigned. [Series detail checklist](SERIES-DETAIL-TODO.md)

In Library’s **Files** tab, use **Assign volume or chapters** to correct the coverage of a specific file. Enter a volume alone for an entire volume, or enter the chapter labels it contains. Clear both fields to restore detected coverage. Files from alternate local groups linked to the same AniList entry can be edited from the shared series page.

## File organization

**Tools → Organize** opens a paginated file inventory for any configured folder. Follow a shortcut from a series to retain its filter. Use file-level moves and renames, batch previews, manual chapter coverage and verified volume editing there. File operation history shows the results and supports guarded restoration. Library keeps file browsing and playback alongside short links into Tools. Import retains contextual review controls and links to the same batch organizer.

## Maintenance action menu

**Tools → Maintenance** queues scans for all or selected library folders through the existing scanner and shows per-folder progress. **Clear artwork cache** removes stored cover images and reports their logical size. That action waits for active scans and file operations to finish. The catalog, local metadata suggestions, reader progress, source media and recovery copies remain available. Scanning rebuilds the artwork.

Provide separate reset levels for catalog, progress and configuration. The preview lists affected records, retained data and consequences for a fresh scan or reconfiguration. A catalog reset clears and rebuilds the selected inventory and associations while preserving identity references needed by retained progress and recovery records. Progress reset explicitly targets reading state. Configuration reset targets selected editable settings, preserves server identity and credentials, and keeps root references required for recovery even if active settings are reset. Implement from an allowlisted record inventory under a verified backup and exclusive maintenance fence. Refuse or defer while affected operations are active, require dedicated confirmation and make interruption recoverable. Every level preserves media bytes, trash and recovery files and the records needed to restore them. [Backup and recovery](UPGRADE-RECOVERY.md) · [Managed trash](DUPLICATE-AND-TRASH.md)

In **Maintenance → Data resets**, select the level and, for catalog or configuration, the affected folders. Type the phrase shown in the preview to apply. The catalog reset removes selected file inventory, series bindings and associations exclusive to those files. The configuration reset clears the selected folders’ display names, intake targets and managed permissions, and assigns the Library role. The progress reset clears saved positions and read status for the signed-in account. Backups and completed resets appear in **Recent resets**. Folder scans and file operations must be idle before the reset can commit.

## Confirmed workflow decisions

| Decision | Status |
| --- | --- |
| Library admission | Confirmed series plus AniList or manual metadata on a scanned file. Missing covers remain an intake issue. |
| Destination routing | One saved target library per Import folder. Filter-based routing follows in a later release. |
| Maintenance reset | Separate previewed catalog, progress and configuration levels. Preserve media and recovery files. |

Build volume navigation and the read-only Tools entry points first. Stage guarded intake and maintenance mutations behind their existing safety work. [Task and test gates](EXPANDED-BACKLOG.md)
