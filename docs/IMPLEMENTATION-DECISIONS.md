# Implementation decisions

**Owner-approved baseline, contingent on the audit gates.** On 2026-11-25 Toronto, the owner approved starting with Mihon-compatible extension downloads, standalone Windows, a Docker/Unraid WebUI, physical file organization and duplicate management. The baseline uses .NET 10, React/TypeScript and SQLite, Apache-2.0 for original code, a separately installed Suwayomi companion and read-only library roots by default. The owner added remote reading and progress sync across Android, Windows and Linux through one primary server, with optional client uploads and subscriptions to additional servers. [Remote reading requirements](REMOTE-READING.md) · [Audit completion ledger](source-audit/COMPLETION-LEDGER.md)

The owner then asked to merge the audit work and start implementation. The first slice covers the shared WebUI, owner authentication and a persistent primary-server identity. The applicable evidence and platform gates remain in the ledger for subsequent features and release qualification.

| Decision | Proposed choice | First acceptance evidence |
|---|---|---|
| Initial scope | Use the shared UI/API and read-only multi-root inventory for basic metadata corrections, exact file identity and duplicate review. Implement server-hosted reading and progress handoff using that shared catalog. Follow with reviewed organization and manual Suwayomi downloads and imports. | The same synthetic library scans on Windows and Docker. File bytes and paths survive the scan. Exact copies, hardlink aliases and unknown identities appear separately. An authenticated reader resumes a chapter opened on another platform. |
| Technology | Use one .NET 10 / ASP.NET Core backend, React with TypeScript, and SQLite in local appdata. Use the same API and UI on Windows and Docker. Use a local browser for the first standalone Windows mode and a single server writer. | Windows runs without Docker. Both targets persist settings and scan state across restart. The database lives outside binaries and outside network media shares. |
| Server and clients | Give one Windows or Linux primary the main library and authority over its progress. The first reader uses the shared WebUI and one owner account across Android, Windows and Linux. Keep optional subscriptions and device upload workflows scoped to the selected server and account. | Clients resume from the same primary after a device switch. A second subscription retains its own catalog identity. An explicitly selected upload goes through verified import on the primary. [Acceptance cases](REMOTE-READING.md#acceptance-cases) |
| Suwayomi | Support a separately installed, operator-controlled Suwayomi companion. The operator configures extension trust and installation in Suwayomi. Manga Organizer handles manual search, downloads through one persistent queue and reviewed import. Qualify `v2.4.2373` as the first candidate and reconcile ambiguous download starts against engine and file state. | A synthetic or authorized chapter survives the observed timeout, appears once in the organizer library and carries source and chapter provenance. |
| Project license | Apply the approved Apache-2.0 choice to original Manga Organizer code when implementation starts. Review resolved dependencies and packaging notices before releasing artifacts. Upstream applications provide behavior references. Suwayomi, third-party extensions, content, models and datasets stay outside the distribution. | Record the chosen dependency versions and their notices. | File mutation policy | Create every library root as read-only. Qualify the target storage and verify backup and restore before enabling managed file changes. Quarantine restores correctly and never selects an alias or alternate edition solely from a name match. |

## Owner feature selection

On 2026-11-25 Toronto, the owner approved the staged formats, first WebUI reader, core library and download workflow, and deferral of the remaining candidates. On 2026-11-26 Toronto, the owner expanded the catalog, duplicate, trash, reader and recovery scope described below. Apply the current decisions within each parent feature. [Feature selection register](FEATURE-SELECTION.csv)

| Area | Included scope | Deferred scope |
|---|---|---|
| Catalog and metadata | Read-only multi-root inventory, basic metadata lookup and corrections, stable work and chapter IDs, edition-specific numbering maps, release attributes with provenance, and bulk release correction. [Identity and migration](RELEASE-IDENTITY.md) | Unrelated provider integrations, general-purpose bulk editing, automatic repack and assembly, and extra browse features. |
| Reader | One owner with right-to-left and continuous vertical reading and progress handoff. Include strict and flexible release preferences, verified chapter ranges, and in-reader switching with logical reading anchors. [Reader formats](REMOTE-READING.md#reader-formats) · [Release policy](READING-CONTINUITY.md) | Household accounts, offline downloads, reflowable EPUB, unrelated reader controls, annotations and external tracker sync. |
| Organization and duplicates | Exact and overlapping release review, read-only comparison of repacks and similarity, persistent intentional alternatives, whole-batch impact previews and reviewed moves into managed trash. Confirm and revalidate storage changes and preserve journaled recovery. [Duplicate and trash policy](DUPLICATE-AND-TRASH.md) | Unattended deletion of active media, automated repair, hardlink creation and seeding integration. |
| Trash and upgrade recovery | Configurable managed trash with a 30-day default expiration for deliberately trashed entries, single or bulk restore, confirmed permanent purge and emptying. Verify a WAL-consistent backup before incompatible upgrades and rehearse restore before enabling the new storage lifecycle. [Backup and recovery](UPGRADE-RECOVERY.md) | Destructive routes remain disabled wherever their platform guarantees are unqualified. |
| Acquisition | Operator manages trusted extensions in the separately installed Suwayomi instance. Manga Organizer checks companion compatibility, searches configured sources, accepts manual download requests in one persistent queue, reconciles retries and stages verified imports for review. [Extension workflow](EXTENSIONS.md#initial-workflow) | Scheduled wanted-list downloads, extension management in Manga Organizer, torrents, Usenet, host-managed companion packaging and Mihon backup migration. |

The owner also selected WebUI editing of persistent library and intake folders, with a server folder browser. Files in intake may move automatically once the metadata and volume or chapter association is unambiguous or the owner has made the association manually. Reading eligibility is based on format support, including files without an association. Managed moves follow the existing storage qualification, backup, revalidation and recovery requirements. [Import intake and association](FILE-ORGANIZATION.md#import-intake-and-association)

The owner selected series grouping from folder names and comparable titles, batch series assignment with chapter coverage resolved separately, chapter-based links for volumes and same-chapter release variants, hash-based relinking after file moves, and cover previews from `cover.png` or the first readable page. The owner prioritized an expandable WebUI with side navigation on desktop, responsive mobile navigation and a quicker server folder picker. Future Android screens follow the WebUI's navigation and interaction patterns. [Catalog identity and association](CATALOG-ASSOCIATION.md)

The expanded selection supersedes the earlier deferral of release language and edition metadata, release-aware duplicate classification, managed-trash retention and purge, advanced release selection, chapter page mapping and cross-release continuity. Legacy quarantine remains recoverable during the transition and is outside automatic expiration without explicit enrollment. Preserve the pending status of unrelated upstream candidates. [Backlog and PR order](EXPANDED-BACKLOG.md) · [Acceptance and qualification](EXPANDED-ACCEPTANCE.md)

The owner also selected a dedicated Tools hub, confirmed-series and AniList/manual metadata admission to Library, default attention issues in Import, one saved Library target per Import folder and independent previewed reset levels. Missing covers remain an attention issue and do not block Library eligibility. Reset levels preserve media and recovery files. [Tools and intake](TOOLS-AND-INTAKE.md)

### Optional features

- **Device uploads** (F25) let a client submit selected files to the primary for validation and review before import. [Upload requirements](REMOTE-READING.md#optional-upload-from-a-device)
- **Additional server subscriptions** (F68) let a client browse and read other servers with separate library identities and credentials. The primary owns the main library and its progress. Subscribed-library progress sync policy is deferred. [Server and client responsibilities](REMOTE-READING.md#server-and-client-responsibilities)

All remaining candidates are deferred for later owner selection. The ledger tracks the outstanding source, license, storage and runtime evidence for the selected scope. [Audit ledger](source-audit/COMPLETION-LEDGER.md) · [Target qualification](source-audit/DEPLOYMENT-QUALIFICATION.md)
