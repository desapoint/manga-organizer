# Initial implementation decisions

**Owner-approved baseline, contingent on the audit gates.** On 2026-11-25 Toronto, the owner approved starting with the five required outcomes, using .NET 10, React/TypeScript and SQLite, licensing original code under Apache-2.0, using a separately installed Suwayomi companion, and starting libraries read-only with later reviewed changes and no permanent deletion in the initial scope. The five outcomes are Mihon-compatible extension downloads, standalone Windows, a Docker/Unraid WebUI, physical file organization and duplicate management. [Audit completion ledger](source-audit/COMPLETION-LEDGER.md)

| Decision | Proposed choice | First acceptance evidence |
|---|---|---|
| Initial scope | Build the five required outcomes in stages. Start with the shared UI/API, read-only multi-root inventory, exact file identity and duplicate review. Follow with reviewed organization and the extension download and import workflow. Include only supporting portions of pending features that are needed for these outcomes, subject to explicit selection. | The same synthetic library scans on Windows and Docker. File bytes and paths survive the scan. Exact copies, hardlink aliases and unknown identities appear separately. |
| Technology | Use one .NET 10 / ASP.NET Core backend, React with TypeScript, and SQLite in local appdata. Use the same API and UI on Windows and Docker. Use a local browser for the first standalone Windows mode and a single server writer. | Windows runs without Docker. Both targets persist settings and scan state across restart. The database lives outside binaries and outside network media shares. |
| Suwayomi | Support a separately installed, operator-controlled Suwayomi companion. Qualify `v2.4.2373` as the first candidate with capability checks, verified source packages and isolated staging. Route ambiguous start outcomes through engine and file reconciliation. | A synthetic or authorized chapter survives the observed timeout, appears once in the organizer library and carries source and chapter provenance. |
| Project license | Apply the approved Apache-2.0 choice to original Manga Organizer code when implementation starts. Review resolved dependencies and packaging notices before releasing artifacts. Upstream applications provide behavior references. Suwayomi, third-party extensions, content, models and datasets stay outside the distribution. | Record the chosen dependency versions and their notices. Check release SBOMs and any redistribution exceptions for their actual artifacts. |
| File mutation policy | Create every library root as read-only. On a managed root, permit an explicitly confirmed and revalidated no-clobber rename, move, relink or quarantine after target qualification. Retain the journal and a restore path. Keep permanent deletion and automatic purge out of the initial scope. | A collision, changed file, lost mount or interrupted move preserves the original and leaves a recoverable record. Quarantine restores correctly and never selects an alias or alternate edition solely from a name match. |

Reader parity, public sharing, tracker sync, torrents/Usenet, optional data and models, extra platforms and other pending features await separate selection. Planned release tests use synthetic data and require the corresponding build or artifact. Known gaps in upstream sources still apply to any feature that relies on them.
