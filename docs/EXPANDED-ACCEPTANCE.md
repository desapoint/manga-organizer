# Expanded acceptance and qualification

These are required acceptance scenarios for the owner-approved expansion. Existing behaviors and prior PR checks are listed in the [backlog](EXPANDED-BACKLOG.md#baseline-to-reuse). The scenarios below describe evidence to gather for the new scope. They are not current pass results. Use synthetic or authorized archives, disposable roots and test owners. Rollout tests must record exact build, OS, filesystem or mount identity, fixture revision, procedure and observed result.

## Platform qualification

| Target | Required verification | Evidence boundary |
| --- | --- | --- |
| Windows x64 | Packaged installer and portable upgrade/rollback, NTFS no-clobber and hardlink identity, Windows reparse points and ACLs, open handle conflicts, simultaneous server/upgrade, restore/purge crash recovery and actual reclaimed bytes. | GitHub Windows jobs can run fixtures. Record packaged install/upgrade results separately from real media root evidence. |
| Non-root Docker Linux | Bind-mounted primary appdata and media with explicit UID/GID, writable/readonly roots, supported cross-filesystem staging, container reinstall/restart, SQLite WAL backup and expected path identity, restore and purge. Include amd64 and release arm64 checks where applicable. | Container smoke tests record image digest, host filesystem and mount configuration. They are not an Unraid pool test. |
| Actual Unraid amd64 | Exercise the supported share/pool layout with Docker path translation, same-pool rename and qualified cross-boundary route, restart, mount loss and return with altered identity, link-count accounting, backup restoration and journal reconciliation. Record share and backing filesystem. | Use authorized disposable paths on hardware. An ordinary Docker runner cannot close this gate. |
| Reader on Android, Windows and Linux | Use the WebUI on the real devices for chapter start, RTL, profile fallback, in-reader alternatives, reconnect and resume handoff. Test against Windows and qualified Docker/Unraid primaries. | Chromium desktop/mobile fixtures verify UI behavior. Real handset and target-host results are separate. |

Keep hosted `foundation.yml`, `migrations.yml` and packaging jobs as regression gates. Add purpose-built fixtures and post-merge qualification records when behavior ships. Record any unavailable platform as **Needs testing** or **Blocked** with the missing evidence. Keep risky mutation routes disabled until their per-platform cases pass.
