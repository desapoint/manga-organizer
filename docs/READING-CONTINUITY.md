# Release selection and reading continuity

This specification owns the reading preference policy, release-specific chapter boundaries (F71), and cross-release position transfer inside the reader (F72). F04, F21, F37 and F41 cover release metadata, reading preferences and progress. The primary server owns validation and synchronization. [Canonical identity](RELEASE-IDENTITY.md) · [Client contract](REMOTE-READING.md)

## Release selection

Persist global preferences, per-series overrides, and explicit per-chapter release choices. A reading-session profile carries the active release's known attributes across chapters and is separate from persistent choices. Allow ordered preferred languages, translation groups, officiality, black-and-white/color, censorship, publication editions, image quality, format, and standalone/chapter-volume-collection presentation. Rules can be strict or flexible. For a strict attribute, a genuinely unknown or conflicting value does not pass by default.

1. Filter to accessible, available, readable releases linked to the requested chapter. Evaluate explicit strict per-series rules before global rules for the same attribute. A series rule replaces that field's global rule. Remaining global strict rules still apply. Never admit unreadable content because a saved ID exists.
2. Honor the explicit chapter selection if eligible. A conflicting deliberate choice requires a visible, scoped override or a replacement selection. A stale selection remains visible as unavailable. It does not erase the saved preference.
3. Rank eligible candidates by active session profile agreement, then applicable series preferences, then global preferences. Within each level apply the configured ordered attributes and their ordered values lexicographically, with unknown values last for flexible rules. This preserves early preferences such as language before relaxing a later preference such as group. Keep a deterministic final tie-break using stable release and asset IDs. Show the matching profile or the first meaningful relaxation when a release is selected.
4. If the strict filter yields no candidate, show the blocked attributes and let the reader choose an explicit session exception, change settings or stop. Where only flexible rules differ, choose the highest eligible candidate and explain the fallback. An explicit chapter pick is durable only when the reader saves it as preferred.

For the next chapter apply the same policy to the current profile even across physical assets, volumes or collections. Use the verified in-asset chapter range when available. Reevaluate eligibility if a location vanishes. Never silently switch to an incompatible language or content variant under a strict rule. The series chapter list should show available releases, relevant attributes, preferred and session status, why a fallback occurred, and a quick way to change the choice. Preserve file-open behavior when a chapter has no verified boundaries and label the available full-file entry. [Acceptance A14–A16](EXPANDED-ACCEPTANCE.md)

## Chapter boundaries

Maintain five independent layers of evidence. Canonical chapter identity establishes *which chapter*. Publication manifests establish *edition membership*. Release coverage establishes *which chapters this asset contains*. A boundary establishes *actual page positions in that specific content*. A correspondence links *positions across content versions*. Each has its own provenance and conflicts.

A proposed `chapter_page_range` stores canonical chapter ID, release/asset ID, content digest or content ID, page-order revision, zero-based inclusive first and last page, source evidence, confidence, verification state, manual override and mapping version. Permit unknown bounds and partially resolved ranges. Validate bounds against a readable ordered manifest. Display conflicts when evidence disagrees, including overlaps or unmatched extras. Keep physical page ordering unchanged by RTL, zoom, crop or spread rendering. A manual correction can change a boundary without silently rewriting progress or completion.

Treat explicitly indexed chapter folders, chapter-specific page filenames and local digital navigation offsets as possible boundary evidence only after checking them against real manifest entries and order. Embedded ComicInfo may describe page roles or counts. Qualify any actual boundary capability from samples. A verified volume-to-chapter edition list, provider chapter labels, source IDs and acquisition provenance can establish identity or membership without a page offset. Align with separately verified individual chapter releases using strong ordered page evidence. Evaluate title-page detection and optional OCR only as review candidates until accuracy and licensing are qualified. Manual boundaries can be explicitly verified by the user. Never divide volume pages evenly and report the intervals as verified. Check covers, author credits, TOCs, title pages, blank pages, ads, bonus illustrations, spreads, joined/split pages and edits.

Opening a chapter at a verified boundary starts there if no chapter-specific resume exists. A saved physical resume for another chapter in the same volume does not override it. A missing or uncertain range keeps the archive readable and clearly offers full-file open or manual review.

## Switching inside the reader

Keep two positions. Store logical chapter progress and the last logical anchor under the owner and canonical chapter. Keep per-content physical page index and revision in the existing progress path. A deliberate switch transfers the active logical position and records the chosen session release. Preserve unrelated physical resumes, explicit chapter completion and other chapters' state. Validate revisions and update IDs on the primary. Side-by-side preview and uncertain estimates do not persist a page or completion.

1. Identify the current canonical chapter and source page in the versioned source manifest. Resolve the target asset and chapter boundaries. If either is unresolved, offer a labeled approximate or manual choice only where appropriate. Never present a guessed position as a match.
2. Reuse a verified correspondence for the two content IDs, chapter ID, order revisions and boundary versions. Prefer exact ordered image hashes with contextual neighboring pages when duplicate cover/credit images collide.
3. Estimate relative position within the bounded chapter, then compare a small window around the estimate with neighboring sequence anchors. Assess normalized pixel, downscaled grayscale or perceptual fingerprints first. Escalate only for bounded hard cases to regional/feature comparison and sequence alignment. Score confidence and the margin against alternative candidates. Benchmark thresholds against authorized or synthetic fixtures before enabling verification.
4. Handle different compression, dimensions, speech bubble text, color, censorship, crops, borders, inserts, missing and reordered pages, and split or combined scans. Allow one-to-many or ambiguous mapping rather than forcing equal page indices. On a low-confidence or conflicting result offer nearby previews, approximate status, previous/next adjustment and explicit confirmation. Save verified manual corrections with their revisions.
5. Cache confirmed correspondences separately from estimates using stable content IDs, chapter ID and boundary, manifest and algorithm versions. A rename preserves cache entries. Changed bytes, page order or boundaries invalidate affected entries and retain prior reading evidence for review.

The reader selector stays available without leaving the reader, identifies the active release and its salient attributes, and uses the same filter and fallback messaging as the series list. Apply one validated switch and position update using the primary's revision contract. On stale requests or unreachable assets leave the current reader state usable.
