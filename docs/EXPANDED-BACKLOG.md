## Status vocabulary

**Planned** has approved scope and no active implementation. **In progress** has an active branch. **In review** has a reviewable submission. **Needs changes** requires a correction. **Blocked** has a known unmet dependency or decision. **Partially implemented** has reusable shipped behavior with scope remaining. **Implemented** has landed code. **Needs testing** has implementation awaiting functional or platform evidence. **Completed** satisfies its mapped acceptance and qualification gates. **Deferred** excludes the work from this sequence. A passing build alone does not move a task to Completed.

P0 gates the next compatible upgrade or safe mutation, P1 enables approved workflows, P2 follows the underlying data and safety gates. Complexity is relative to the current code. Automated tests and platform evidence are mandatory where listed. “None now” in the owner column means the documented policy is enough to start. Research gates are distinct from requests for clarification.

## PR sequence

1. Commit this planning baseline. First implementation PR adds the pre-upgrade backup and restore guard (MO-001). Use existing schema fixtures to exercise the guard before introducing a new data migration.
2. Review additive IDs and the legacy crosswalk separately from the release schema (MO-002 and MO-003). Isolate backfill/cutover checks from new interactive workflows.
3. Add local extraction and shared bulk editing (MO-004), then persistent alternative decisions and grouped comparison (MO-005).
4. Land impact previews and journaled trash/restore before adding the purge worker. Review trash admission (MO-006) and irreversible purge (MO-007) in separate PRs.
5. Land preference policy (MO-008) and verified page boundaries (MO-009) as separate PRs. After their data contracts are tested, add matching (MO-010) and in-reader switching (MO-011).
6. Record functional, upgrade, storage and device qualification by slice, then verify the integrated release (MO-012). Keep unrelated deferred work in the existing feature register.

For the Tools follow-up, land the read-only volume navigation correction (MO-013) independently of schema work, then the Tools index and review routes (MO-014). Build the fast association and metadata queue (MO-020) and file organization workbench (MO-021). Stage Versions (MO-015) and the Library/Import eligibility and target routing work (MO-016–MO-017) in separate PRs. Add non-destructive Maintenance (MO-018) before previewed resets (MO-019). [Tools and intake specifications](TOOLS-AND-INTAKE.md)

Use small PRs based on the last checked dependency or main after it merges. A parallel spec or fixture can proceed without downstream schema changes. Hold any destructive route behind its own qualified storage and restore evidence. Keep exact revision, workflow links and actual failure outcomes in the qualification ledger.
